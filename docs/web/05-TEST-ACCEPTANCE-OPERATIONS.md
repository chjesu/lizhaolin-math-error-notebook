# 测试、验收与运维基线

| 属性 | 内容 |
|---|---|
| 版本 | `0.1` |
| 状态 | 待评审 |
| 覆盖范围 | Web、MySQL、OSS、Agent、迁移、发布与恢复 |

## 1. 测试策略

### 1.1 单元测试

- 权限矩阵与资源归属判断。
- 上传 MIME、大小、路径和文件名规范化。
- JSON Schema 和候选输出限制。
- 幂等键、任务状态转换和重试上限。
- SQLite/MySQL 方言映射后的业务函数。
- 答案隐藏和推荐 `verified=1` 硬约束。

### 1.2 集成测试

- Web → Worker → Agent Gateway → 质量门 → MySQL。
- Web/Worker → 私有 OSS 上传、预览和短时下载。
- 判题、推荐、复习、attempt 和 PDF 全链路。
- RDS 连接中断、模型超时、OSS 失败和任务恢复。
- 数据库事务失败时不产生半完成业务记录。

### 1.3 回归测试

现有测试继续是业务行为基线，重点覆盖：

- `grade-preview → grade-commit`。
- `recommend-packet → assign-recommendations`。
- `prepare-review-batch → verify-review-batch`。
- `daily-review-packet` 和复习阶段推进/更正。
- `practice_sheet.py` 数学公式、图形、答案开关和打印开关。
- UTF-8、中文全文检索、题号与哈希大小写。

### 1.4 安全测试

- 未登录、越权和跨学生访问。
- 普通用户调用管理接口。
- 上传伪造扩展名、超大文件、损坏图片和路径穿越。
- 图片/文档中的提示词注入。
- 模型输出 SQL、Shell、URL、路径时不被执行。
- 签名 URL 过期、越权对象读取和 Bucket 公共访问检查。
- 数据库账号 DDL、跨库和管理权限应被拒绝。

## 2. 核心验收用例

| 编号 | 场景 | 预期结果 |
|---|---|---|
| AC-001 | 学生上传一张清晰错题照片 | 生成任务；视觉模型查看全部预览；结果逐题展示。 |
| AC-002 | 照片缺题干或关键步骤 | 不补造，明确指出需补拍的局部。 |
| AC-003 | 错误题判定 | 包含原题、学生作答、第一处错误、完整解析、答案和下一步。 |
| AC-004 | 完全正确题 | 简洁判定和关键核验，不错误录入错题。 |
| AC-005 | 推荐练习 | 全部题目已验证、未作答、非近重复，显示来源/难度/理由。 |
| AC-006 | 生成练习 PDF | A4 可读，默认无答案、不打印，图形尺寸合理。 |
| AC-007 | 提交推荐题结果 | 正确更新 attempt 和推荐状态，不重复记录。 |
| AC-008 | 完成复习 | 只推进当前阶段；更正误判不重复推进。 |
| AC-009 | 重复提交同一照片 | 返回已存在任务或结果，不重复写错题。 |
| AC-010 | Agent 输出恶意命令 | Schema/策略拒绝，不执行、不写库并留审计。 |
| AC-011 | 未验证题被模型选中 | 保存质量门拒绝。 |
| AC-012 | 管理员纠正判题 | 原记录和纠正记录均可追溯。 |

## 3. 数据迁移验收

迁移必须生成机器可读报告和人工摘要，并满足：

1. SQLite 迁移源健康检查通过。
2. MySQL schema 版本正确。
3. 所有业务表行数一致或差异均有迁移规则解释。
4. 主键、唯一键、外键和关键内容哈希通过。
5. 题目、审核、错题、复习、推荐、attempt 的关联完整。
6. 推荐中未验证题为零。
7. 选定中文搜索案例结果达到人工认可的等价性。
8. 备份恢复后重复执行上述校验仍通过。

## 4. 性能基线

以下是 MVP 验收目标，不包含远端模型自身推理时间：

- 20 个并发用户下，普通页面/API 的 P95 响应不高于 2 秒。
- 创建后台任务的接口 P95 不高于 1 秒。
- 模型任务必须立即返回可查询的 `job_id`，页面不得长连接等待完整判题。
- 一次提交只开启短数据库事务，模型调用和文件上传期间不得持有事务。
- 相同输入的缓存命中不得再次调用模型或重复写库。

若测试环境规格不足，报告实际结果和瓶颈，不通过删除质量门来换取性能。

## 5. 发布验收门

### Gate A：代码完成

- 单元、集成和现有回归测试通过。
- 文档、schema migration 和配置模板同步更新。
- 无生产密钥和数据进入仓库。

### Gate B：安全完成

- RDS 无公网访问。
- OSS Bucket 私有。
- 权限矩阵和 Agent 越权测试通过。
- 日志脱敏和密钥轮换流程可执行。

### Gate C：迁移完成

- 正式迁移报告通过。
- 备份和回滚演练通过。
- 项目发起人批准切换。

### Gate D：产品完成

- 学生、家长主流程验收通过。
- PDF 样例通过视觉检查。
- 判题结束均有明确下一步。
- 低清和争议任务能正确进入补拍/确认队列。

## 6. 监控与告警

至少记录：

- Web 5xx、延迟和登录失败。
- 任务排队、运行、失败、重试和耗时。
- 模型调用次数、Token/费用、超时和 Schema 失败。
- `grade-preview`、`verify-review-batch`、推荐保存的拒绝原因。
- MySQL 连接、慢查询、存储和备份状态。
- OSS 上传失败、签名失败和对象缺失。
- 管理员删除、纠正、验证、迁移和恢复动作。

告警不得包含学生作答正文、完整图片链接、密码或模型密钥。

## 7. 备份与恢复

### 7.1 数据库

- 使用 RDS 自动备份，并按业务恢复目标配置保留策略。
- 定期生成加密逻辑备份，保存到独立受限位置。
- 定期在非生产实例执行恢复演练。
- 记录恢复用时、恢复点和校验结果。

### 7.2 OSS

- Bucket 默认私有并启用服务端加密。
- 为原始上传、标准化预览和生成 PDF 定义不同生命周期。
- 删除业务记录前检查审计与保留要求；不得由模型直接删除对象。

## 8. 常见故障处理

| 故障 | 首要动作 |
|---|---|
| 模型超时 | 保留任务和输入哈希，按策略重试一次或进入人工队列。 |
| Schema 不合法 | 不写库，记录模型/提示词版本和精简错误。 |
| RDS 不可用 | 停止写入，任务保持待处理，不切换到本地第二主库。 |
| OSS 不可用 | 不创建缺少证据的判题任务；等待恢复后重试。 |
| PDF 失败 | 保留结构化练习包，可重试生成，不改变推荐状态。 |
| 推荐质量门拒绝 | 不降级为未验证题，返回推荐缺口。 |
| 发现迁移差异 | 停止切换，保留证据，从迁移源重新演练。 |

## 9. 定期运维

- 每日：任务失败、备份状态、错误率和异常管理操作。
- 每周：模型成本、低置信度比例、推荐缺口和慢查询。
- 每月：恢复抽查、权限审计、依赖与安全更新评估。
- 每次发布：数据库迁移预演、关键业务回归、PDF 样例和回滚检查。

正式频率可按使用规模调整，但恢复演练、权限审计和题库质量门不得取消。
