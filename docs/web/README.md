## 1. 文档目的

本目录把 Web 改造讨论固化为可评审、可实施、可验收和可运维的项目基线。所有文档均受根目录 `AGENTS.md`、`PROJECT_ARCHITECTURE.md` 和项目级 `math-error-notebook` Skill 约束。

本目录描述目标态，不表示对应功能已经上线。未经迁移验收和正式切换，不得把 RDS MySQL 声明为生产主库，也不得让本地 SQLite 与云端数据库同时作为活动写库。

## 2. 已确认的核心决策

| 编号 | 决策 |
|---|---|
| D-001 | 第一阶段建设邀请制多用户、多租户 Web 版；支持家庭租户，并为未来学校租户保留兼容边界，但不建设计费型完整 SaaS。 |
| D-002 | 已确认：应用与数据库物理分离；生产关系型数据库固定采用阿里云 RDS MySQL 8.0，不再评估其他关系型数据库。 |
| D-003 | ECS、RDS 位于同一地域和 VPC，RDS 默认不开放公网。 |
| D-004 | 照片、试卷和 PDF 存私有 OSS；数据库仅保存业务数据、对象键、哈希与审计信息。 |
| D-005 | Web 层复用现有判题、审核、推荐、复习和 PDF 质量门，不建立平行业务实现。 |
| D-006 | Agent 只产生候选 JSON；模型无数据库、Shell、任意文件和任意网络权限。 |
| D-007 | 第一版不引入向量库、Redis、Celery、微服务或独立前端工程。 |
| D-008 | PDF 默认无答案、不打印；云端生成后由浏览器下载或本地打印。 |
| D-009 | 采用共享 MySQL schema，以 `tenant_id`/`student_id` 隔离学习数据，不采用每用户一库。 |
| D-010 | 已验证公共题库全租户只读共享；错题、作答、推荐、复习、上传和 PDF 按租户与学生隔离。 |
| D-011 | 异步任务首版使用 MySQL 持久任务表和一个 Worker；只有监控证明需要时才引入 Redis、消息队列或多 Worker。 |

## 4. 文档治理

- `草案`：仍存在影响范围或架构的未决问题。
- `待评审`：内容完整，等待项目发起人确认。
- `已批准`：可以进入对应实施阶段。
- `已废止`：被更新决策替代，但保留历史。

变更流程：提出变更 → 标明受影响的需求/架构/验收编号 → 更新讨论纪要或决策记录 → 评审 → 修改基线 → 代码实现与测试 → Git 提交。

不得只修改实施代码而不更新受影响的项目文档，也不得用规划文档覆盖当前系统事实。
