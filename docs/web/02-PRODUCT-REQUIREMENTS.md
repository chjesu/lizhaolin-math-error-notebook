# 产品需求文档（PRD）

| 属性 | 内容 |
|---|---|
| 产品 | 李兆霖数学错题本 Web 版 |
| 版本 | `0.1` |
| 状态 | 待评审 |
| 产品阶段 | MVP |

## 1. 产品目标

让学生和家长无需进入本地项目或命令行，也能完成“提交作答 → 获得可信判题 → 明确下一步 → 完成针对性练习 → 分阶段复习”的完整闭环，同时保持现有项目对证据、题库验证、推荐和审计的标准。

## 2. 成功标准

- 学生可以使用手机完成照片上传、查看判题和提交后续练习。
- 每次判题都有逐题结论；错误题包含第一处实质错误、正确过程和明确下一步。
- 推荐题全部来自已验证题库，并显示难度、来源和推荐理由。
- 学生提交前不泄露答案；PDF 默认无答案、不自动打印。
- 模型不能直接写库，所有写入都有质量门和审计记录。
- 迁移后只有一个生产主库，数量、关系和关键内容与迁移源一致。

## 3. 用户与角色

### 3.1 学生

- 上传作答照片。
- 查看自己的判题、错题、推荐练习和复习任务。
- 记录推荐题与复习结果。
- 在规则允许时查看解析和答案。

### 3.2 家长

- 查看孩子当前任务、历史和薄弱项。
- 查看、确认或纠正判题结果。
- 调整推荐难度，生成复习 PDF。
- 移除误保存错题或确认已经掌握。

### 3.3 管理员/审核员

- 管理授权来源、试卷导入和题目审核。
- 查看异常任务、审计记录和系统状态。
- 执行受控迁移、备份、恢复和版本升级。
- 无权绕过题目验证门或批量直接更新 `verified`。

## 4. MVP 范围

### 4.1 学生端页面

1. 登录页。
2. 今日任务首页。
3. 照片上传页。
4. 判题任务状态页。
5. 判题详情与下一步页。
6. 错题详情与历史页。
7. 推荐题/复习 PDF 下载页。

### 4.2 家长端页面

1. 学习概览。
2. 错题与复习阶段列表。
3. 判题纠正与错题管理。
4. 推荐难度调整和 PDF 生成。
5. 异常、补拍和待确认列表。

### 4.3 管理端最小范围

1. 题库与错题统计。
2. 后台任务状态和失败原因。
3. 模型调用审计摘要。
4. 数据库备份状态。

试卷批量导入与验证第一阶段允许继续由服务器上的受控 CLI 执行；管理 Web 化作为后续里程碑。

## 5. 功能需求

### 5.1 身份与权限

| 编号 | 需求 |
|---|---|
| FR-AUTH-001 | 未登录用户不得访问学习数据和对象文件。 |
| FR-AUTH-002 | 学生只能访问自己的任务和记录。 |
| FR-AUTH-003 | 家长只能访问已绑定的学生。 |
| FR-AUTH-004 | 管理操作使用独立角色，并记录操作者和时间。 |
| FR-AUTH-005 | 对象文件通过短时授权访问，不提供永久公开链接。 |

### 5.2 照片判题

| 编号 | 需求 |
|---|---|
| FR-GRADE-001 | 接受受支持的图片格式并校验实际 MIME、大小和数量。 |
| FR-GRADE-002 | 执行方向、白底、尺寸控制和哈希缓存，不做本地 OCR 判题。 |
| FR-GRADE-003 | 具备视觉能力的模型必须查看全部预览。 |
| FR-GRADE-004 | 每道可见题单独判定；不清楚时明确要求补拍。 |
| FR-GRADE-005 | 错误/部分正确必须保存第一处实质错误、完整解析和最终答案。 |
| FR-GRADE-006 | 每次结果必须包含具体“下一步”。 |
| FR-GRADE-007 | 相同图片重复提交必须幂等，不重复创建错题。 |

### 5.3 推荐与复习

| 编号 | 需求 |
|---|---|
| FR-REC-001 | 推荐候选必须满足 `verified=1`。 |
| FR-REC-002 | 已作答题、近重复题、占位题和不完整题不得重新推荐。 |
| FR-REC-003 | 推荐显示来源、难度和理由。 |
| FR-REC-004 | 推荐难度随复习阶段和最近表现变化。 |
| FR-REV-001 | 每个活动错题同一时刻只暴露一个可执行阶段。 |
| FR-REV-002 | 错误或部分正确时启动新的自适应复习周期。 |
| FR-REV-003 | 误判更正不得重复推进复习阶段。 |

### 5.4 PDF

| 编号 | 需求 |
|---|---|
| FR-PDF-001 | 复用 `practice_sheet.py` 生成 A4 PDF。 |
| FR-PDF-002 | PDF 默认不含答案、不打印。 |
| FR-PDF-003 | 仅在明确授权后生成答案页。 |
| FR-PDF-004 | 云端仅生成与下载；自动家庭打印不属于 MVP。 |

### 5.5 管理与审核

| 编号 | 需求 |
|---|---|
| FR-ADMIN-001 | 题目导入必须保存来源、许可和原始记录。 |
| FR-ADMIN-002 | 未验证题不得进入推荐。 |
| FR-ADMIN-003 | 审核结论通过 `verify-item/verify-review-batch` 提交。 |
| FR-ADMIN-004 | 删除、纠正、确认掌握、批量审核和恢复需显式确认。 |

## 6. 核心业务规则

1. 不清晰内容不得补造。
2. 无直接证据不得把错因归为“粗心”。
3. 模型生成题不能自动标记为已验证题。
4. 推荐只使用已验证题。
5. 答案默认隐藏到提交后或用户明确请求时。
6. 模型只提交候选输出，正式状态改变由业务服务完成。
7. 当前 SQLite 与未来 MySQL 不得同时作为活动主库。
8. 文件授权、来源和验证历史不得在迁移中丢失。

## 7. 非功能需求

| 编号 | 类别 | 需求 |
|---|---|---|
| NFR-001 | 安全 | RDS 仅内网访问，最小权限账号，密钥不进入前端和模型上下文。 |
| NFR-002 | 隐私 | 最小化保存未成年人个人信息，日志不记录图片正文和敏感凭证。 |
| NFR-003 | 可靠性 | 长任务可查询、重试和断点恢复；重复请求不重复写入。 |
| NFR-004 | 可追溯 | 保存输入哈希、模型/提示词版本、候选哈希、质量门和提交编号。 |
| NFR-005 | 可恢复 | 数据库和对象文件有独立备份；发布前完成恢复演练。 |
| NFR-006 | 性能 | 普通页面与数据库查询不受模型时延阻塞；模型任务异步执行。 |
| NFR-007 | 可维护 | Web 复用现有业务入口，不创建平行推荐器、验证器或 PDF 实现。 |
| NFR-008 | 编码 | 应用、迁移、数据库连接统一使用 UTF-8/`utf8mb4`。 |
| NFR-009 | 可访问 | 手机浏览器可用；关键操作不只依赖颜色表达状态。 |

## 8. MVP 不包含

- 多学校多租户计费。
- 教师班级管理系统。
- 实时聊天社区。
- 向量数据库和通用知识库问答。
- 本地 OCR/本地视觉模型判题。
- 自动抓取未授权试卷。
- 家庭打印机远程控制。
- 原生 iOS/Android 应用。

## 9. 产品验收摘要

MVP 只有在学生完整走通照片判题、订正、推荐练习、复习记录和 PDF 下载，家长能纠正误判，管理员能查看审计与恢复数据，并且 Agent 无法绕过质量门写库时，才可视为产品闭环完成。
